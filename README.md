# EV Monitor

ระบบบริหารกองยานรถยนต์ไฟฟ้า — 3 container แยกกัน

```
 เบราว์เซอร์ ──► web  (Next.js 14)  ──/api/v1/*──►  api  (Fastify + TypeScript)  ──►  db  (PostgreSQL 16)
                :3000   หน้าเว็บ + พร็อกซี              :4000  REST + OpenAPI /docs         :5433 (เฉพาะเครื่องนี้)
                                                         ▲
                       อุปกรณ์ / ระบบภายนอก ──── X-API-Key ── /api/v1/ingest/*
```

| โฟลเดอร์ | หน้าที่ |
|---|---|
| [`db/`](db/README.md) | PostgreSQL: schema + ข้อมูลตั้งต้น/เดโม (สคริปต์ init) |
| [`api/`](api/README.md) | REST API: อ่าน/จัดการข้อมูล + `/ingest/*` ให้ระบบภายนอกส่งข้อมูลเข้า + สิทธิ์ตามบทบาท |
| `app/` | เว็บ Next.js: เรียก API ผ่าน `/api/v1` ใน origin เดียวกัน (cookie httpOnly ไม่ต้องตั้ง CORS) |
| `design/` | ต้นแบบ HTML และสเปก (`design/HANDOFF.md`) |

## เริ่มใช้งาน

```bash
cp .env.example .env     # แล้วตั้ง POSTGRES_PASSWORD และ AUTH_SECRET (ดูวิธีสุ่มค่าในไฟล์)
docker compose up --build -d
```

- เว็บ: http://localhost:3000 (ปรับพอร์ตด้วย `WEB_PORT`) — เข้าสู่ระบบเดโม `admin@evmonitor.co.th` / `demo1234`
  (ฟอร์มเติมให้อัตโนมัติเมื่อตั้ง `NEXT_PUBLIC_DEMO_LOGIN=อีเมล:รหัสผ่าน` ใน `.env`)
- เอกสาร API: http://localhost:4000/docs
- **รถเดโมจะเป็น "ออฟไลน์" หลังไม่มีข้อมูลเข้าเกิน 30 นาที** (job ตรวจออฟไลน์ของ API) — เปิดตัวจำลอง telemetry ด้วย `docker compose --profile demo up -d`
- ล้างข้อมูลแล้วสร้างใหม่จากข้อมูลเดโม: `docker compose down -v && docker compose up --build -d`

ผู้ใช้เดโม (รหัสผ่านเดียวกัน): `admin@evmonitor.co.th` (admin) · `prasit@company.co.th` (manager) · `wanna@company.co.th` (viewer — เห็นเฉพาะรายงาน)
**ข้อมูลเดโมและรหัสผ่านนี้ต้องลบ/เปลี่ยนก่อนใช้งานจริง** (ดู `db/README.md`)

## ติดตั้งแบบกองยานว่างเปล่า (ใช้งานจริง)

ค่าเริ่มต้นใส่ข้อมูลเดโม (รถ 12 คัน คนขับ 12 คน ผู้ใช้ 3 คนที่ใช้รหัส `demo1234` ฯลฯ) สำหรับลองระบบ — ติดตั้งใช้งานจริงให้เริ่มจากศูนย์:

```bash
# .env — มีผลตอนสร้างฐานข้อมูลครั้งแรกเท่านั้น (volume ว่าง)
SEED_DEMO=false
ORG_NAME=บริษัท ตัวอย่าง จำกัด       # ไม่บังคับ — แก้ภายหลังได้ที่ ตั้งค่า > องค์กร
FLEET_NAME=กองยาน EV สำนักงานใหญ่
ORG_CITY=ขอนแก่น                      # เมืองและจุดกึ่งกลางแผนที่ (ไม่มีหน้าตั้งค่า) — เว้นว่าง = กรุงเทพฯ
ORG_LAT=16.4419
ORG_LNG=102.8360
NEXT_PUBLIC_DEMO_LOGIN=               # ต้องว่าง (ค่านี้ฝังตอน build เว็บ: เปลี่ยนแล้วต้อง docker compose build web)
```
```bash
docker compose up -d --build
docker compose exec api node dist/cli.js create-admin --email you@company.co.th --name "ชื่อ นามสกุล"   # ยังไม่มีผู้ใช้เลย — สร้างผู้ดูแลคนแรก
```

จากนั้นเข้าเว็บด้วยบัญชีนั้นแล้วเริ่มใส่ข้อมูลจริง (ฐานข้อมูลมีเฉพาะค่าตั้งค่า กฎแจ้งเตือน รุ่นรถตัวอย่าง และสมมติฐานของรายงานที่ปรับได้):

1. **ตั้งค่า > การเชื่อมต่อ > สร้างคีย์** — ออก API key ให้อุปกรณ์/ระบบที่ส่งข้อมูลรถ (`/api/v1/ingest/*`, ดู api/README.md)
2. **เพิ่มสถานีชาร์จ** ที่หน้า "การชาร์จ" (ปุ่ม "เพิ่มสถานี": ชื่อ ประเภท Depot/สาธารณะ เครือข่าย กำลังชาร์จ จำนวนช่อง ราคา พิกัด — เริ่มต้นที่จุดกึ่งกลางแผนที่ขององค์กร) ต้องมีสถานีก่อนจึงจะบันทึกการชาร์จของรถได้ · **เพิ่มคนขับ / เพิ่มรถ** ในหน้าคนขับและรถทั้งหมด (หรือส่งผ่าน ingest API)
3. **เชิญผู้ใช้** ที่ ตั้งค่า > ผู้ใช้และสิทธิ์ · ตั้งค่าอีเมล/LINE ตาม `.env.example` ถ้าต้องการแจ้งเตือน
4. **รายงานความพร้อมเปลี่ยนเป็น EV:** ที่หน้า "รายงาน" แท็บ "ความพร้อมเปลี่ยนเป็น EV" กด "เพิ่มรถสันดาป" กรอกรถที่ยังเหลือ (ระยะวิ่ง ค่าน้ำมัน คะแนนความพร้อมที่ประเมินเอง รุ่น EV ที่แนะนำ) และ "ตั้งค่า TCO" กรอกรายการต้นทุน 5 ปีของรถสันดาปเทียบ EV — ว่างจนกว่าจะกรอก
5. ทุกหน้ารับมือข้อมูลว่างได้ (แสดง 0 / "–" พร้อมข้อความแนะนำ) และมีชุดทดสอบ `api/test/empty-fleet.test.ts` คุมไว้

ตัวเลขเปรียบเทียบกับปีก่อนในรายงานเป็น 0 จนกว่าจะมีข้อมูลจริง (แก้ได้ที่ตาราง `report_config`)

## ผู้ดูแลคนแรกและรหัสผ่านเดโม (ก่อนเปิดให้ผู้ใช้จริง)

ข้อมูลตั้งต้นมีบัญชีเดโม 3 บัญชี (`admin@evmonitor.co.th`, `prasit@company.co.th`, `wanna@company.co.th`) ที่ใช้รหัสผ่านตั้งต้น `demo1234` — **ใครรู้ก็เข้าได้** ระบบจึงเตือนผู้ดูแลด้วยแบนเนอร์สีแดงทุกหน้า ป้าย "รหัสตั้งต้น" ในตารางผู้ใช้ และคำเตือนใน log ของ API ตอนเริ่ม ขั้นตอน (ผ่านบรรทัดคำสั่ง ไม่ต้องล็อกอินเว็บก่อน):

```bash
# 1) สร้างผู้ดูแลระบบจริง (ถามรหัสผ่านโดยไม่แสดงตัวอักษร ≥8 ตัว มีตัวอักษรและตัวเลข; รหัส demo1234 ถูกปฏิเสธ)
docker compose exec api node dist/cli.js create-admin --email you@company.co.th --name "ชื่อ นามสกุล"
# 2) เข้าสู่ระบบเว็บด้วยบัญชีใหม่ให้ได้ก่อน แล้วปิดบัญชีเดโมทั้งหมดที่ยังใช้รหัสตั้งต้น
docker compose exec api node dist/cli.js retire-defaults
```

- `retire-defaults` ปิด (ไม่ลบ) เฉพาะบัญชีที่ยังใช้รหัสตั้งต้น และ **ปฏิเสธถ้าจะไม่เหลือผู้ดูแลที่ใช้งานอยู่** (บัญชีที่เจ้าของเปลี่ยนรหัสแล้วไม่ถูกแตะ) — ปิดแล้ว session เดิมหลุดทันที เปิดกลับได้ที่ ตั้งค่า > ผู้ใช้และสิทธิ์ (ต้องเปลี่ยนรหัสผ่านก่อน)
- คำสั่งอื่น: `list-users` · `check-defaults` (แสดงบัญชีที่ยังใช้รหัสตั้งต้น; exit code 2 ถ้าพบ ใช้ในสคริปต์ตรวจก่อนขึ้นระบบได้) · `set-password --email …` (ตั้งรหัสให้บัญชีที่ลืม/ถูกยึด — ทุกอุปกรณ์ถูกออกจากระบบ)
- ใส่รหัสผ่านทาง stdin สำหรับสคริปต์: `printf '%s' "$PW" | docker compose exec -T api node dist/cli.js create-admin --email … --name … --password-stdin` — **ไม่รับรหัสผ่านทาง argument** เพื่อไม่ให้ติดใน history/รายการโปรเซส
- ระบบห้ามตั้งรหัสผ่านเป็น `demo1234` ทุกช่องทาง (เปลี่ยนรหัส ตอบรับคำเชิญ รีเซ็ต CLI)
- บน Windows ใช้ PowerShell/CMD (หรือ Git Bash พร้อม `MSYS_NO_PATHCONV=1`) · หมายเหตุ: ถ้าติดตั้งด้วยข้อมูลเดโมไว้แล้ว ข้อมูลเดโมอื่น (รถ คนขับ ฯลฯ) ยังอยู่ — ถ้าต้องการเริ่มสะอาดให้ติดตั้งใหม่แบบกองยานว่างเปล่า (หัวข้อด้านบน)

## เปิดใช้ HTTPS (Caddy)

service `caddy` เป็น reverse proxy ที่ขอและต่ออายุใบรับรอง Let's Encrypt ให้เอง ไม่ทำงานโดยปริยาย (โปรไฟล์ `https`):

1. ให้โดเมนของคุณ (เช่น `ev.company.co.th`) ชี้ DNS มาที่เครื่องนี้ และเปิดพอร์ต **80 และ 443** สู่อินเทอร์เน็ต (พอร์ต 80 จำเป็นต่อการออกใบรับรอง)
2. ตั้งค่าใน `.env` **ทั้งชุดนี้พร้อมกัน**:

```bash
DOMAIN=ev.company.co.th
ACME_EMAIL=ops@company.co.th          # แนะนำ: Let's Encrypt แจ้งเตือนเมื่อใบรับรองใกล้หมดอายุ
COOKIE_SECURE=true                    # cookie เข้าสู่ระบบส่งเฉพาะผ่าน HTTPS
APP_BASE_URL=https://ev.company.co.th # ลิงก์ในอีเมล (คำเชิญ/รีเซ็ตรหัส/รายงาน)
TRUST_FORWARDED_FOR=true              # เว็บใช้ IP ผู้เรียกจริงที่ Caddy ตั้งให้ (rate limit ต่อ IP)
WEB_BIND=127.0.0.1                    # ปิดการเข้าเว็บแบบ HTTP ตรงจากภายนอก — เข้าได้ผ่าน Caddy เท่านั้น
NEXT_PUBLIC_DEMO_LOGIN=               # เว้นว่าง (ไม่เติมรหัสเดโมในฟอร์ม)
```

3. `docker compose --profile https up -d` แล้วเปิด `https://<DOMAIN>` (HTTP จะถูกเปลี่ยนเป็น HTTPS อัตโนมัติ และส่ง HSTS)

**ทดสอบในเครื่องโดยไม่มีโดเมน:** ใช้ `DOMAIN=localhost` (ค่าเริ่มต้น) — Caddy ออกใบรับรองจาก CA ภายในของตัวเอง เบราว์เซอร์จะเตือนว่าไม่น่าเชื่อถือจนกว่าจะนำ root CA ของ Caddy (ใน volume `caddy_data` ที่ `/data/caddy/pki/authorities/local/root.crt`) ไปเชื่อถือ — ทดสอบด้วย `curl -k https://localhost` ได้ทันที

หมายเหตุ: ใบรับรองและกุญแจอยู่ใน volume `caddy_data` **อย่าลบ** (ขอใหม่บ่อยจะชนเพดานของ Let's Encrypt) · Caddy เขียนทับ `X-Forwarded-For` ด้วย IP ผู้เรียกจริง (ค่าที่ผู้โจมตีใส่มาไม่ผ่าน) และไม่หน่วงสตรีมเรียลไทม์ (SSE) · ถ้ามี reverse proxy/load balancer ของคุณอยู่หน้า Caddy อีกชั้น ต้องตั้งให้ส่ง IP จริงต่อมาและปรับ `header_up` ใน `proxy/Caddyfile` ให้ใช้ค่านั้น (ดู SECURITY.md)
